# Fare Scout

面向出国游的低价机票发现与价格监控。用户可以选择具体日期、日期范围、节假日或周期性出行时段，也可以选择一个或多个目的地。这个目录记录了 2026-11-01 前的产品讨论和查价实验，是后续开发的起点。

## 用户问题与产品定位

用户希望按自己的出行意愿持续发现便宜的出国机票，而不必反复手动搜索。出行意愿可以是固定往返日期、一段可出发日期、节假日、每周末，或其他自选期限；目的地也可以是固定城市、一个候选集合或某个区域。香港出发、周六凌晨起飞、周一凌晨抵港、去东南亚多个目的地，只是第一个试验场景。用户可自行配置出发地、目的地、时段、飞行时长和提醒条件。

价格判断应基于**同一目的地、同一往返日期、相同乘客与舱位条件**的报价采样。新建监控没有此前 90 天的自有采样；未满 90 天应标注“监测期最低”，不能称作“三个月最低”。实时报价可能在点击预订链接时变化。

## 第一个试验场景：香港周末出行

- 出发机场：香港 HKG。
- 出发：周六当地时间 00:00–05:59。
- 返回：周一当地时间 00:00–05:59 **抵达香港**；目的地起飞可以发生在周日夜间。
- 展望期：未来 12 个周末；经济舱，1 名成人。
- 首批目的地：曼谷 BKK、普吉 HKT、清迈 CNX、新加坡 SIN、吉隆坡 KUL、槟城 PEN、巴厘岛 DPS、胡志明市 SGN、岘港 DAD、马尼拉 MNL。
- 为排除绕路行程，试验代码要求每程最多 1 次中转、每程不超过 8 小时。这是试验过滤条件，需根据用户反馈调整。

## 目前完成的验证

使用 [Kiwi.com 官方 MCP](https://www.kiwi.com/ko/pages/mcp/)取得了真实往返报价。2026-11-01 对最近一个周末（11 月 7 日出发、9 日抵港）的 10 个目的地各查询一次，在上述时间和飞行时长条件下，仅新加坡返回匹配行程：周六 01:40 香港起飞，周日 20:20 新加坡起飞，周一 00:10 抵港，报价 HK$4,760。另 9 个目的地在本次接口返回的有限结果里没有匹配，不能推断市场上没有航班。Kiwi 查询曾出现 HTTP 503，因此查询失败与无匹配必须分别展示。

此前还用上海—东京固定日期的示例验证了 SQLite 采样与比较：两次成功查询分别记录 CNY 2,858 和 CNY 2,343。短时间内报价会变，提醒应附核价链接。

`prototype/flight_watch.py` 是固定航线、固定日期的早期监控代码；`prototype/weekend_watch.py` 是香港周末多目的地的试验脚本。两者都从原工作目录复制到这里作为参考，**尚未启动后台定时任务，也没有上线给其他用户**。后者只写 SQLite 并在终端输出，不发送推送。

## 给其他用户使用的第一版

前端先做手机可用的网页，包含三个主要页面：

1. 创建监控：出发地、目的地或目的地集合、固定日期或可出行日期范围、节假日/周期性时段、往返时间、人数、舱位、最长飞行时间和提醒条件。
2. 机会列表：按出行日期与目的地展示符合条件的航班、往返总价、可游玩时长、中转与行李信息、核价链接。
3. 监控详情：同一行程的采样价格曲线、采样覆盖时间、最近查询时间、降价记录以及失败状态。

后端建议从 FastAPI、服务端渲染页面、PostgreSQL 和独立定时 Worker 起步。Worker 生成需要查询的航线/日期组合，向数据源查询并保存原始报价与标准化报价；相同查询由多个用户订阅时共享一次采样，再分别判断提醒。邮件可作为首个通知渠道。数据源通过适配器隔离，避免业务逻辑绑定 Kiwi。

核心数据对象：`users`、`watches`、`search_jobs`、`offers`、`price_observations`、`notifications`。监控条件应存结构化数据；自然语言可以帮助用户填表，但须展示解析后的条件供用户修改。定时查询、价格历史和通知判断不依赖 Agent loop，也不需要先接 DeepSeek Harness。

## 数据源与边界

最新接入状态和候选源核查见 [docs/DATA_SOURCES.md](docs/DATA_SOURCES.md)。地点目录已新增 Travelpayouts，实时报价仍来自 Kiwi。

- [Kiwi MCP](https://www.kiwi.com/ko/pages/mcp/)：已实测可取当前报价，返回的是有限结果；`empty` 只表示本次结果无匹配。
- [SerpApi Google Flights Price Insights](https://serpapi.com/google-flights-price-insights)：文档有 `price_history`，但未实测目标航线，也未承诺完整覆盖 90 天。只有当前价与历史价口径可比时才用于“近 90 天最低”。
- [Expedia Price Tracking](https://www.expedia.com/why/price-tracking)：部分航线在 App 内展示价格历史，适合竞品研究；未验证可程序化获取。
- [Skyscanner MCP](https://developers.skyscanner.net/docs/mcp-server)：目前按合作案例开放，不作为个人 MVP 的接入前提。

## 本地试跑

### 本地网页第一版

使用 Python 3.9+，无需安装额外依赖：

```bash
python3 -m app.server
```

打开 http://127.0.0.1:8765，注册或登录后默认进入「搜特价」，也可切换「出行监控」创建监控。
新监控默认自动进行首次查价，也可暂停后点击「查一次价格」。
每个账号分别保存监控、价格记录、提醒和收件邮箱；发信服务由服务管理员统一配置。
旧单人版账号需通过本机终端输出的初始化入口设置密码，已有数据保留在指定账号下。
账号与部署边界见 [docs/ACCOUNTS.md](docs/ACCOUNTS.md)。
地点支持按全球/内地热门、港澳台、各地区及普通护照互免精选浏览；输入搜索覆盖全部城市、国家和机场，无需先选类型。停留晚数支持双滑块，详见 [docs/LOCATION_DISCOVERY.md](docs/LOCATION_DISCOVERY.md)。
新增「搜特价」：选择出发日期范围、停留晚数、出发星期和预算，目的地可不限或指定范围，按返回报价发现可去的城市，再转成监控草稿。
内置中国内地七类假期快捷选，搜特价填出发范围、创建监控填固定往返日期；2027 年暂为标注待公布的参考窗口，详见 [docs/HOLIDAYS.md](docs/HOLIDAYS.md)。
调研、数据口径和边界见 [docs/DEAL_SEARCH.md](docs/DEAL_SEARCH.md)。搜索结果暂存服务内存，刷新/重启不保留页面结果。
支持固定往返日期、周末出行；出发地和目的地均可选择国家/地区、城市或具体机场，目的地可混选。
地点目录支持中文、英文和 IATA 代码，包含 253 个国家/地区、9,521 个城市和 9,186 个机场条目；目录收录不代表有可售航班。
支持人数、总预算、每程最长时长与中转次数；新监控默认不限制时长及中转，当前仅经济舱和港币。
机会卡片展示机场全名、航空公司、航班号、往返时间与时长，并可展开航段与行李件数详情。
当前数据源不返回行李重量和尺寸，须在预订页核对最终额度。
周末最多连续四周，时间窗口按实际出发/返回机场当地时间筛选；固定模式返程日期为目的地起飞日。
每轮最多查询 12 组日期与地点范围，其余组合在后续轮次顺序轮询；旧监控保留原有 8 小时/1 次中转条件。
同一国家/城市的查询保留多个实际行程，价格比较按实际往返机场与日期分开。
数据保存在本地 `fare_scout.db`；手动查询需要联网访问 Kiwi。
自动查价默认每 6 小时一次，可设置为 1/3/6/12/24 小时或暂停。计划与提醒保存在本地数据库，
关掉网页仍会执行；电脑需保持唤醒、本地服务需持续运行。过期行程自动停止查询。
同一行程降价满 HK$100（可修改）或首次进入预算时生成网页提醒，可选 SMTP 邮件投递。
邮件配置见 [docs/EMAIL.md](docs/EMAIL.md)，发信凭据填在已忽略的 `.env` 中，不能写进代码。
目前没有邮箱验证、自助密码找回、节假日或日期范围配置，服务仍仅监听本机。

运行必要测试：`python3 -m unittest discover -s tests -v`。
架构地图见 `docs/ARCHITECTURE.md`，进展见 `PROGRESS.md`。
