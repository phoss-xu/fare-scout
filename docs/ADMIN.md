# 只读管理后台与面试讲解

## 访问与范围

Workers 版入口为 `/admin`，复用已有登录会话。先在首页登录，再访问管理地址。
本功能不接入保留的 Python 版；它读取线上实际使用的 D1 表，不再维护第二份后台数据。
后台与 `0010_admin.sql` 已随 `b4c86ca` 部署到 Workers。该版本未写入 `ADMIN_USER_IDS`；部署时保留 Cloudflare 仪表盘变量，实际开放范围取决于该变量现有值。变量缺失或为空时，所有账号都会被拒绝。

管理员由服务端环境变量 `ADMIN_USER_IDS` 配置，值是已有账号 ID 的逗号分隔列表，如 `1,3`。
默认缺失或空值拒绝所有账号，不会把首个注册者或某个邮箱自动提升为管理员。
账号 ID 应由管理员通过可信的数据库只读查询确认；各环境单独配置，不能从前端传入。
本地使用 `.dev.vars`；生产配置须在用户验收、授权发布后单独设置。该变量不是登录凭据，但更改它属于授予访问权限。

先应用增量迁移，再启动更新后的 Worker：`npm run db:local`、`npm run dev`。
本地使用 http://localhost:8787/admin 。保持 `MAIL_ENABLED=false`，没有真实查价验收需求时保持 `QUERY_ENABLED=false`。
已有数据不初始化、不导入、不清空。新增 `0010_admin.sql` 只增加心跳表与查询索引。

## 四个页面

| 页面 | 读取对象 | 解释边界 |
| --- | --- | --- |
| 运行概览 | 用户数、有效监控、任务积压、过期租约、24 小时采样、邮件队列、调度心跳 | 不是平台 CPU、请求流量或数据库配额仪表盘 |
| 用户 | 昵称、脱敏账号/收件邮箱、有效监控数、Passkey 数、收件状态 | 不返回密钥、会话、密码摘要、验证令牌；收件状态是本地缓存记录 |
| 查价任务 | 状态、批次/用户/监控 ID、尝试次数、源查询时间、缓存复用、错误码、查询日期和地点 | 创建/完成时间属于批次；没有补造单任务开始/完成时间 |
| 邮件状态 | 降价提醒和每日推荐的统一列表、尝试次数、下次尝试、供应商接受时间 | 当前收件邮箱不是历史实际收件邮箱；没有逐次投递尝试和送达回执 |

任务和邮件按用户 ID、状态筛选；每页 25 条，可前后翻页。用户按 ID，任务按内部递增序号，
邮件按创建/计划时间及唯一标识使用游标分页，避免深页 OFFSET。翻页不是冻结快照，期间任务状态仍可能变化。
任务详情不返回完整报价、用户偏好 JSON 或租约令牌。
浏览器将所有动态字段作为文本渲染，用户昵称等内容不能作为 HTML 执行。

后台 API 只允许 GET，数据查询全部是参数化 SELECT；不调用查价、投递、邮箱验证、调度推进函数。
管理员查看不会标记提醒已读或刷新邮箱验证缓存。每个 API 独立验证会话和白名单，HTML 各入口也受保护。
响应不缓存；退出或会话失效后接口返回 401，普通账号返回 403。现有会话认证仍需要读用户/凭据表。

## 运行情况的口径

Cron 每次执行前保存最新一次心跳，完成后记录状态与耗时；异常只保存固定错误码，原异常继续抛出。
单行心跳由 invocation ID 限制回写，较早执行的迟到结果不会覆盖新一轮状态。
心跳超过 5 分钟没有更新显示需要排查；缺失显示未知。该阈值是管理提示，不是可用性承诺。
若进程被强制终止，记录可能停留在执行中；若 D1 自身不可用，页面也无法借助同一个 D1 给出独立的健康证明。
因此心跳需要配合 Cloudflare 平台日志和外部可用性监测，不能单独证明整条链路正常。

24 小时采样按 `observations` 行数统计：一轮查询可能产生多条行程，也可能记录 empty 或 error。
它不是外部请求成功率，不把无匹配当接口失败。最近有匹配报价也不等于最近一次请求成功。
首末采样跨度不是连续覆盖；每条航线的最低价判断仍须保持人数、舱位、币种、机场和日期可比。

邮件 `sent` 仅表示供应商接受发送请求，不代表用户收到。`waiting_verification` 也可能在等待接收确认。
本版复用现有状态，未新增供应商回执、历史收件人快照或投递错误详情；诊断需用记录 ID 对照平台日志。
普通特价任务元数据保留约一小时、监控任务约七天，每日推荐引用的批次不按此规则删除。
所以后台显示的是当前保留记录，不能把它当作完整历史审计系统。

## 面试里先这样介绍（约一分钟）

> Fare Scout 会按用户偏好持续查机票，并在符合提醒条件时发邮件。我用 D1 保存用户、监控、查询任务、报价和投递队列。
> 为了排查用户没收到提醒的问题，我做了只读管理后台，可以从用户 ID 找到查价任务，检查失败、重试和报价，再查看邮件投递状态。
> 管理接口复用登录会话，但单独做服务端管理员授权；所有列表分页，邮箱在 API 层脱敏，页面没有重试或发送操作。
> 我另外记录调度心跳，因为没有任务不代表服务健康。面板会区分无匹配和查询失败，也明确邮件接受与实际送达的区别。

## 常见追问与回答依据

### 为什么用户数据和日志分开？

用户、配置、报价和投递状态是业务事实，需要稳定查询、关联和事务。异常堆栈是诊断信息，进入平台日志。
后台通过任务/批次 ID 串联两者，不保存原始请求、完整供应商响应或秘密凭据。
追问：不是所有日志都需要存进关系表；安全审计和投递尝试若有长期追踪要求，应另建有明确保留策略的记录。

### 只读后台为什么仍要验证权限？

只读也能泄露跨用户数据。身份认证回答“你是谁”，管理员授权回答“你能否查看全站数据”。
服务端每次读取都验证两者，隐藏前端按钮不构成授权控制。
当前少量管理员采用账号 ID 白名单；团队扩大、需要多种权限与授权审计时再改为角色/权限表。

### 两个执行器如何避免领取同一个任务？

`tasks.js` 使用带条件的原子 UPDATE 领取任务，记录租约截止时间与随机令牌。
租约过期可以重新领取，保存结果时再校验令牌、租约和任务有效状态，拒绝旧执行器迟到写入。
这是防重复写入和中断恢复的设计，不能声称外部网络调用绝对只发生一次。

### 报价写入成功但提醒没写进去怎么办？

`tasks.js` 使用 D1 batch；报价插入触发提醒判断，提醒插入再触发发信队列。
相关数据库变化处于同一事务，减少只保存一半的情况。独立的邮件执行器之后领取队列。
外部发信不在数据库事务内；供应商接受后进程退出，仍可能在回写前产生重试窗口。
项目传递稳定幂等键，但端到端防重复效果取决于供应商支持和保留期限，不能宣称 exactly-once。

### 为什么用游标分页和索引？

列表只取 26 条，用额外一条判断有无下一页，只返回 25 条，避免一次加载全部记录。
游标基于有稳定排序的 ID 或时间加 ID。索引服务于实际筛选和排序，参数化查询隔离输入与 SQL。
概览仍有聚合扫描、邮件列表有 UNION 排序；这版没有证明大数据量性能。增长后应量测 rows_read、耗时和执行计划，
再按需增加按日汇总或缓存，不能仅凭建了索引就宣称高并发能力。

### 你实际验证了什么？

用 workerd 和临时 D1 做权限、分页、脱敏、状态口径、只读无任务推进及心跳测试；外部请求被阻止。
浏览器验收要另记录桌面/手机操作结果。模拟数据验证不等于真实 Kiwi 查询、真实邮件送达或生产负载测试。
Workers 代码与迁移已发布；真实账号管理员白名单需另行配置后才会开放访问。本次未授予新的管理员权限。

## 后续可以扩展

有实际需要后补投递尝试表和历史收件人快照、管理员操作审计、独立可用性监测、采样与每日推荐保留策略。
增加重试/暂停按钮时需重新设计写权限、CSRF、操作记录及通知幂等，本版不预先提供这些动作。

实现依据：[D1 prepared/batch API](https://developers.cloudflare.com/d1/worker-api/d1-database/)、
