# 版本与更新日志

顶部版本按钮在登录前后均可打开更新日志，按新到旧展示，支持全局语言、字体和主题。版本及条目唯一来源是 `app/static/releases.js`；两种服务均直接提供该静态文件，无数据库迁移。`PROGRESS.md` 继续记录开发与验收过程，更新日志只写用户能感知的变化。

## 版本规则

从 `0.1.0` 开始采用 `主版本.次版本.修订号`：新增功能递增次版本，修复和小幅改进递增修订号；重大不兼容变化递增主版本。产品仍在早期阶段，先使用 `0.x.y`。预览使用 `0.1.0-preview.1`，同一目标版本继续预览时递增最后的数字。

当前首项为 `0.1.0`，发布日期为北京时间 2026-11-05。此前没有统一版本号的历史记录保留已有提交编号，不倒推编号或补造发版记录。目前仅回填 README 已记载的 2026-11-03 / `85ad7c1`。

## 每次发版

1. 在首项整理本次实际要发布的改动，按 `added`（新增）、`improved`（优化）、`fixed`（修复）分组，分别填写 `zh` / `en`。不要将尚未包含的改动写入发布条目。
2. 用户验收并授权发布后，在待发布代码中把首项版本去掉 `-preview.N`，将 `status` 改为 `published`，`date` 填实际发布日（北京时间 `YYYY-MM-DD`）。发布失败或取消时恢复预览状态，不留下已发布记录。
3. 执行必要检查和已授权的发布流程。同一份文件同时决定当前版本按钮及日志内容，无需另改前端常量或数据库。
4. 下次开发时在数组最前面添加新的预览项，保留历史项。`version` 对有编号的版本必填；旧记录允许 `version: null`，用 `revision` 保存原提交编号。预览 `date: null`，页面显示“尚未发布”。

不要把包依赖版本、Git 提交号或本地构建时间当作产品版本。历史条目随代码版本长期保存、可审阅、可回滚；此阶段通过仓库维护，无在线编辑后台。
