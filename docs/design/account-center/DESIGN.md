# Fare Scout：用户中心与偏好设置设计

2026-11-10。设计提案与交互原型，未替换线上或本地正式界面。原型状态、手机号验证码、示例会话均用于评审；不读取真实账号，不发邮件或短信，不保存个人数据。

## 方向

延续现有页面的暖纸色、墨色、衬线排印、风景背景，设置使用紧凑的编辑面板。取消每行大圆图标、宣传式英文副标题、占满屏幕的大折叠项。正文14px、辅助信息12px、页标题24–28px，操作触控区至少44px。复用项目根字体与主题tokens。

头像菜单作为唯一的登录用户入口：个人资料、偏好设置、通知、安全与登录、退出登录。点击后在同一个用户中心中进入对应栏目。游客仍有独立偏好入口；登录后顶部不再同时放置功能重叠的设置按钮和空洞账号菜单。

默认推荐「侧栏面板」：桌面约850px宽、左侧184px导航、右侧内容；手机转为页面内横向栏目导航、单列设置。全页与右侧轻抽屉作为可切换备选：全页适合未来复杂账号管理，轻抽屉适合只有少量偏好时；当前项目采用面板的阅读与任务切换成本较合适。

## 信息归属

| 栏目 | 内容 | 交互与范围 |
| --- | --- | --- |
| 个人资料 | 头像、昵称、收件邮箱、手机号 | 编辑头像/昵称；联系方式独立验证，邮箱与手机号互不替代 |
| 偏好设置 | 语言、显示货币、字体、主题、风景更换 | 当前支持的偏好即时生效；当前阶段标明设备范围，后续账号同步再迁移 |
| 通知 | 已验证收件邮箱、降价邮件、每日推荐邮件 | 总渠道偏好与每条行程提醒取交集；逐行程目标价/间隔仍在「我的行程」 |
| 安全与登录 | 登录身份、通行密钥、密码、会话 | 仅显示当前账号可用的登录方式；不把收件邮箱认证误写成登录身份变更 |
| 关于 | 当前版本、更新日志 | 版本与日志仍读取releases.js，不另设版本来源 |
| 风景本身 | 换图、喜欢、下载、摄影来源、许可、风景收藏入口 | 来源和许可随当前照片，在照片名称旁展开；收藏可在该处打开，不占用账号设置 |

手机号的产品用途：可验证的联系方式；当前通知仍以邮箱和网页为主。不因绑定手机号暗中增加短信提醒、短信登录或找回入口。手机号要有可确认用途后再正式显示；首版没有短信适配器时，该行从正式页面隐藏。

## 身份和验证流程

收件邮箱和登录邮箱是不同用途。首版明确显示收件邮箱；登录身份放安全栏目。更换收件邮箱不修改登录邮箱和账号标识。新地址验证前邮件暂停；恢复本人曾认证的精确地址可按现有规则复用。

邮箱：输入 → 发送链接 → 待验证 → 点击链接 → 必要时登录 → 认证成功。显示剩余重发时间，发送失败保留邮箱并允许重试；过期/已使用/错误账号给出对应操作。真实服务接受与已验证是两种状态，不把发送成功当作认证成功。

手机号：选择国家区号 → 输入手机号 → 发送短信 → 6位验证码 → 认证成功。需短信服务、号码规范化、限流、验证码哈希/过期/次数限制；敏感换绑时再验证原登录凭据。没有验证码验证不能显示已绑定。

头像：上传 → 裁剪 → 保存；默认用昵称首字。需图片类型/体积检查、解码重编码、去除元数据、对象存储、访问控制和旧文件回收。默认头像先行，不直接保存任意外链。

昵称：40字内，去首尾空白；页面统一使用该昵称。资料保存需明确提交；偏好即时生效并保留键盘可访问性。

## 数据与后端边界

当前已具备：用户name/email/notification_email、密码/Passkey登录、邮箱认证、每日推荐与逐行程提醒；偏好保存在当前浏览器。尚不具备：头像字段与对象存储、已验证手机号与短信适配器、资料更新接口、Passkey增删管理、设备会话管理、密码修改/找回、独立的通知渠道总开关与账号偏好同步。

实施需要新增profile与validated contact模型，联系方式认证记录带用途/用户/地址或号码/状态/时间。通知总开关属于账号数据，推荐时段和逐行程提醒继续各自持久化；邮件发送同时检查邮箱已认证、账号渠道偏好、该任务开关。偏好同步应使用账户配置与游客设备配置的显式迁移，退出后不泄露前一账号偏好或资料。

## 交付顺序

1. 统一入口与面板，清理失效控件，把现有邮箱验证和实际偏好归位；保持当前后端能力可用。
2. 资料更新、头像存储和裁剪、账号偏好同步，完成真实持久化与权限检查。
3. 有短信服务和产品用途后再交付手机号认证；增加通行密钥管理、密码安全操作、会话撤销时分别核对真实能力。

原型中的交互用于确认信息结构与视觉，不代表上述后端能力已完成。建议先确认面板方案，再按这三步进入产品实现。
