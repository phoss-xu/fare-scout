# 搜特价：调研与本地第一版

核查日期：2026-11-01。

结论：新增独立的发现式搜索，用“出发地＋出发日期范围＋停留晚数”找到可选目的地，选中具体行程后再转成原有固定日期监控。
这解决用户尚未决定去哪、哪天走的问题；原有监控继续负责长期跟踪已选行程。

信心：对现有 Kiwi 接口支持和本地流程较高（已直接读取工具定义、执行真实请求）；对飞猪当前 App 的逐项交互细节较低（官网浏览未成功，无法宣称已复刻当前版本）。

## 产品证据与取舍

- [飞猪官方 App Store 页面](https://apps.apple.com/cn/app/id453691481)介绍按时间、预算和想法发现目的地，以及低价提醒，支持“先探索、再持续关注”的产品方向。
- [飞猪查询入口的公开操作说明](https://nj.bendibao.com/youhui/2025814/175592_4.shtm)显示出发地/目的地到“搜索低价”的流程；此页面是第三方操作资料，不能替代当前 App 实测。
- 历史教程的检索摘要提到模糊日期、多城市、旅行天数和出发星期，但完整教程页面读取受限；本次不把历史数量上限或最长月份当作现版事实。
- [Wego 官方 Anywhere 说明](https://company.wego.com/wego-new-flights-to-anywhere-feature)明确支持先选出发地、目的地不限，再按预算、时长、区域筛选。这为同类发现流程提供可核查的对照，不代表 Wego 接口已接入。
- [Kiwi 官方说明](https://www.kiwi.com/en/cheap-flights/)明确介绍日期范围和 Anywhere 搜索；产品网页能力不能直接等同于 MCP 能力，因此另行实测。
- 飞猪 App Store 上一条 2019 年评论抱怨低价日历变得不直观。它只作为设计反例：保留实际日期与清晰价格，不作为当前产品质量判断。

工程判断：第一版应突出日期范围、目的地可选、晚数、预算与明确价格口径。暂不复制地图、免签/签证标签、权益票卡、促销折扣或虚构价格日历，现有资料/数据不足以可靠支撑这些体验。

## 接口证据

2026-11-01 直接读取 `https://mcp.kiwi.com` 的 `tools/list`，确认 `search-flight` 支持：

- `departureDate` / `departureDateTo`：出发范围。
- `nights_in_dst_from/to`：目的地停留晚数，触发往返查询。
- `fly_days`：上游星期编码 0=周日，本地表单 0=周一，适配时转换。
- `one_for_city`、`price_to`、`max_sector_stopovers`：探索、预算和中转过滤。
- `flyTo` 定义只写地点字符串，未专门保证 Anywhere；实际调用 `flyTo=anywhere` 成功，因此作为已实测而非文档保证能力。

直接请求 HKG、不限目的地、11 月 20–27 日出发、停留 2–4 晚、1 成人经济舱、HKD、禁止自行转机，返回 15 条行程。
当时河内往返 HK$948，11 月 26 日出发、28 日返回；岘港 HK$1,015，24 日出发、28 日返回；富国岛 HK$1,047。
价格是查询时响应，不能保证后续成交价。最终本地适配器还会按实际机场、日期、晚数、星期、预算、时长与中转二次校验。

## 第一版行为

- 工作台新增“搜特价”；出发地支持国家/城市/机场，目的地默认不限，也可选择最多 6 个范围。
- 出发时间可快捷选择未来 30/90/180 天，或自填；跨度最多 180 天，日期在未来一年内。
- 日期方式可选固定往返或灵活日期。固定模式使用两程当地起飞日期，不应用停留晚数和出发星期。
- 灵活日期可多选 1–10 晚（支持不连续选择）；筛选人数、预算、出发星期、中转和每程总时长。目前只支持 HKD、经济舱往返。
- 每个实际目的地城市展示本次返回的较低价；可按价格、出发日期或时长排序。
- 日期栏只显示已有返回报价的日期，未返回的日期不标“无票”，不声称全日期穷举或市场最低。
- 搜索在后台执行，页面轮询进度；部分范围失败单独提示，全部失败与成功空结果分开。
- “持续关注这趟”填入具体机场和日期的监控草稿；用户保存后才创建监控，默认先暂停自动查价。
- 不写入监控价格历史，不发送提醒。搜索任务按账号隔离，保存在本地服务内存中，完成超过一小时后在新搜索时清理；刷新不保留页面结果，服务重启会清除。

## 实现地图与边界

`static/deals.js / deal_views.js / deals.css` → `server.py` → `deal_jobs.py` → `deals.py` → `provider.Kiwi.query`。
地点控件复用 `static/locations.js`；报价详情复用 `flights.js`，未增加依赖或第二报价源。
后台最多 2 个执行线程，每账号最多 1 个在途搜索；总任务数上限 100，完成任务超时清理。
未实现搜索历史持久化、取消任务、单程搜索、完整低价日历、促销折扣验证、签证资格判断。
不同机场返回的行程仍可核价，当前转监控要求去程与返程机场对称，避免静默扩大监控范围。

## 什么会改变方案

若飞猪现版实际流程或用户反馈表明单程、多个出发地比往返更重要，应先扩展出行类型；
若 Kiwi 的有限结果使过滤后频繁为空，应增加可核查覆盖的报价源，再评估多日期分片，不能把空结果当无票。
要做完整日历，需要可覆盖日期矩阵的数据与清晰缓存时效；要做“历史特价”，需要同口径的长期样本。

## 2026-11-03 · 多地区并发与逐批结果（本地待发布）

此前 Python 在单次搜索内依次查询各地区；Workers 每次后台默认只推进一个任务，多个轮询可能重叠，但没有统一的并发上限。前端两种运行时均等待搜索结束才展示。

现在 Workers 通过原子任务领取控制有效运行租约最多 4 个，每次 HTTP 后台并行一批，定时任务按已有配置分批推进；Python 的发现搜索共用 4 个来源线程，周末/地点组合一起进入队列。共享客户端查询进度并提前展示已经返回的报价，失败仍单独标记；未出现的目的地不推断为无航班。相同报价内容不重复重绘卡片和地图。

设计核对了 [Cloudflare 的连接数与后台执行限制](https://developers.cloudflare.com/workers/platform/limits/)：单次 HTTP 后台不连续启动多轮，保留原 22 秒整组请求超时；原 90 秒租约用于异常恢复。并发本身不保证上游固定响应时间。

测试通过受控响应闸门验证四组重叠、跨轮询有效任务不超过上限、任务只领取一次、慢地区未完成时部分报价可读。实际浏览器在明确标注“模拟报价”的独立服务验证 1/6 先展示、6/6 完成及 390px 布局。没有测量真实 Kiwi 提速幅度，也没有部署服务器或发送通知。

### 不同返程机场的行程提醒

从具体行程建立固定日期提醒时，配置 `return_route` 保存实际返程机场。Kiwi MCP search-flight 不提供独立返程机场参数，因此查询使用两端机场各自共同的城市（必要时国家）范围，再按四机场严格过滤完整往返报价；不合并单程报价。查价源返回有限结果，未返回目标航线不能推断市场无票。若两端机场无法归入共同国家范围，创建时明确提示暂不支持。旧提醒不含该字段时继续使用原往返机场规则。
