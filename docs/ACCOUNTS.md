# 账号与数据隔离

> 当前本地开发入口已统一到 `npm run dev` → http://localhost:8787（Wrangler 本地 D1，mixed 登录）。旧 Python 账号和数据已迁入，密码哈希保持不变；8765 已停止运行。下文 Python 账号管理与恢复命令属于旧实现，仅作用于保留的旧库，不用于当前登录页。详见 README 与 docs/ARCHITECTURE.md 的本地统一记录。


## 当前能力

- 邮箱与密码注册、登录、退出；用户保存昵称、登录邮箱与独立收件邮箱。
- 监控、设置、价格记录与提醒均通过 `watches.owner_id` 归属用户。
- 未登录不能读取或修改业务数据；越权访问监控统一返回 404。
- 自动采样在用户退出后继续运行；后台邮件按监控所有者读取收件地址。
- 发信服务是管理员配置，不要求每个用户提供 SMTP 凭据，也不向用户返回凭据。

## 旧数据迁移

迁移前使用 SQLite backup 保留旧数据库副本。`FARE_OWNER_EMAIL` 指定旧记录所属账号；
服务在开放 HTTP 请求前创建预留账号，把原监控归到该账号，保留原采样和提醒。
预留账号没有初始密码，普通注册不能领取该邮箱下的数据；其他注册账号从空白开始。

服务在终端输出 `/setup#token=...` 初始化入口，只供本机操作者使用，有效期两小时。
用户自行设置密码，令牌随后失效；后台调度在预留账号激活后继续执行。
令牌只保存摘要，放在 URL 片段中以避免进入 HTTP 请求日志；页面读取后移除片段。
重启会保留未过期的初始化令牌；过期后为尚未激活的账号生成新入口。
服务启动时不会为已设置密码的账号自动重置密码或重新发令牌。
不要通过公共 API 暴露初始化令牌。

本机操作者可使用 `python3 -m app.accounts set-password <邮箱>` 按用户要求设置或更新密码。
密码从隐藏输入读取，不放入命令参数；操作会撤销该账号所有旧会话和初始化令牌。

## 本地忘记密码

登录页「忘记密码？」提供本机恢复方法。原密码只保存校验值，无法查看原文。
在项目终端为已有本地账号生成一次性入口（默认端口 8765，其他端口使用 `--port`）：

```bash
python3 -m app.accounts reset-password-link you@example.com --port 8765
```

打开输出的 `/setup#token=...` 链接，由用户自行设置新密码。设置/重设密码及密码注册均要求再次输入确认，两次不一致会在页面提示并阻止提交。入口有效 15 分钟、只能使用一次；
重新生成会使旧入口失效。生成入口不更改原密码或会话，成功提交新密码后撤销该账号旧会话。
保留账号、监控、收藏和历史记录。只保存令牌摘要，不提供公开的发放 API；
本机恢复依赖本地终端权限，不是邮箱找回，也不适用于云端 Passkey 账号。

## 本地通行密钥（Passkey）

本地 Python 服务同时保留密码与 Passkey 登录，沿用已有账号及数据。先用密码登录，
在「设置 → 登录与通行密钥 → 添加通行密钥」完成设备验证；绑定后登录页可以直接
点击「使用通行密钥登录」，无需填写邮箱或密码。可添加多把密钥，在设置中分别移除，
密码登录与上述本机恢复入口仍可使用。建议保留另一台设备或密码管理器的备用密钥。

请统一使用 **http://localhost:8765**（或服务实际端口）。`127.0.0.1` 可进行密码登录，
绑定密钥时会提示改用 localhost；两者 Cookie 分开，切换地址后需重新登录。
本地 RP ID 为 `localhost`，与生产域名的 Passkey 不通用，不复制线上账号或设备私钥。

安装 Node.js 20+ 并运行 `npm ci && npm run assets:passkeys`。服务端通过本机 Node 子进程调用
项目已有的 `@simplewebauthn/server`；浏览器复用已有 `@simplewebauthn/browser` bundle。
验证库的[官方接口文档](https://simplewebauthn.dev/docs/packages/server)说明注册与认证流程。
数据库幂等增加 `local_passkey_users`、`local_passkeys`、`local_passkey_challenges` 三张表；
仅保存公钥与签名计数，五分钟挑战绑定浏览器 Cookie、来源及绑定账号的当前会话，
服务端强制设备验证并校验签名、RP ID、来源、挑战和计数，验证请求只能使用一次。
绑定、列表和移除接口均要求已登录及 CSRF。凭据发放不接受邮箱来选择其他账号。

验证：`npm run test:local-passkeys` 使用隔离 SQLite 和真实 P-256 签名验证协议；
`python3 -m unittest discover -s tests -v` 包含挑战过期与会话绑定检查。
协议测试不代表已在用户设备上完成指纹、面容或 PIN 绑定，设备操作须用户本人完成。

## 密码与会话

- 密码 6–128 个字符（由用户选择调整），支持中文与空格；随机盐和 PBKDF2-HMAC-SHA256 600,000 次迭代。
- 数据库不保存明文密码，也不保存明文会话令牌。
- 256 位随机会话使用 HttpOnly、SameSite=Lax Cookie，绝对有效期七天，退出后撤销。
- 修改请求要求当前会话的 CSRF 令牌，同时检查 Origin、请求格式和 Host。
- 登录及注册按账号和来源地址计数限流，窗口 15 分钟。
- 持久化账号信息的 SQLite 文件与本地 `.env` 使用仅当前用户可读写的权限。
- 参数参考 [OWASP 密码存储](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)
  与 [会话管理](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)。

## 本地验证与部署边界

当前服务仍仅监听本机，已完成本地账号隔离，不等于已部署给远程用户。
对外部署前应使用成熟的应用服务器/反向代理与 HTTPS，设置 Secure Cookie，
并按实际部署域名调整 Host/Origin 校验；当前 HTTP 处理器只允许本机 Host。
尚未实现邮箱验证、自助找回密码、多因素认证与账号删除。
未验证的登录邮箱不能作为已经证明的邮箱所有权；不应将当前注册流程直接公开上线。

必要测试包括两个账号的读取/写入隔离、逐用户邮件收件人、会话撤销与过期、CSRF、
同源限制以及旧数据保留。测试账号、测试数据库和模拟邮件均与用户账号隔离。
